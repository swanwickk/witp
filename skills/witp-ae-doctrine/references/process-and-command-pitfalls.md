# 宿主命令与进程处置的坑

只在清理进程、起后台任务、或命令莫名返回 `exit -15` 时读本文件。

---

## 一、`pkill -f` / `pgrep -f` 自匹配

模式会匹配到**发出该命令的 shell 自身**，表现为命令直接返回 `exit -15`（SIGTERM）而无任何 pkill 输出。

- 裸模式必自杀：`pkill -f "witprec.exe"`。
- **加方括号只在字面串不出现在同一条命令行其他地方时才有效**：`pkill -f "witpre[c].exe"` 与同行 `grep -F 'witprec.exe'` 组合时，那个裸字面串仍被模式命中，命令行照样被杀。
- **正解**：把目标名用变量拼出来，让字面串在任何位置都不连续出现：
  ```sh
  N="witprec"; N="$N.exe"; pkill -f "$N"
  ```
  或整行只用方括号形式，且**不在别处写裸字面串**。
- 排查进程存活时同理：`grep -c 'set-des[t]'` 这类写法，要确认同行没有裸字面串。

## 二、长耗时游戏命令一律后台

`witp-cmd set-dest` 是**逐轮标定**的：每次移动要多次读屏-校正，单次实测可达 8 轮以上、数分钟，前台容易撞超时。

- 起法：`background=true, notify=true`，返回 `session_id` 后再用读层/界面回读确认结果。
- 前台单次终端调用有超时上限，**不要指望一次长 sleep 等完**；需要长等待就分段，或直接放后台。
- **严禁中途 `pkill` 强杀推进脚本**——让它跑完，用超时兜底。
