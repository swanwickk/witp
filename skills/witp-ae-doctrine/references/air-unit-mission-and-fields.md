# 航空队与编队的任务字段语义（读层判据）

用途：回答「我方飞机/编队到底被指派了什么任务、还有多少力量可用来打击」这类问题。
**一切结论取自读层 `state/*.json`；中队番号与任务字段是两回事。**

---

## 1. 中队番号 ≠ 任务

航母飞行队的番号只表达默认角色：

| 番号 | 默认角色 |
|---|---|
| VF | 战斗机（Fighter）|
| VS | 侦察轰炸（Scouting）|
| VB | 俯冲轰炸（Bombing）|
| VT | 鱼雷（Torpedo）|

任务字段与番号**相互独立、可任意组合**——把 VS 挂对舰攻击、把 VB 改去搜索都合法。
⇒ **不要由名字推断任务，也不要在读出任务字段之前断言「它没被赋予攻击任务」。**

---

## 2. 任务码（`primary_mission_code` / `secondary_mission_code`）

| 码 | 任务 | 交叉验证机型 |
|---|---|---|
| 1 | Airfield Attack | B-17 |
| 3 | **Naval Attack** | 航母 VB / VS / VT |
| 6 | Escort / CAP | F4F |
| 8 | Naval Search | PBY |
| 9 | ASW | 巡洋舰水侦 |
| **16** | **Training**（默认待命状态，不是作战任务） | 陆攻 / 零战中队 |

- 读取器的结构枚举里**只有** `TaskForceMission`，**没有航空队任务码表** → 映射须靠机型交叉验证建立，
  或翻自己的历史报告/SKB 条目复用。
- 读层字段名：`primary_mission_code`、`secondary_mission_code`。

---

## 3. 分配比例与「可用打击力」

`airgroups.json` 导出这些比例字段：`percent_cap`、`percent_lrcap`、`percent_asw`、`percent_search`、`percent_train`、`percent_rest`。

**手册机制**：搜索比例 > 0 时，该比例的飞机飞对海搜索，**其余飞机飞该中队设定的主任务**；
若主任务本身就是对海搜索，则其余飞机休息。⇒ 这些百分比是**占用**，不是**追加**。

```
可用于主任务的飞机比例 = 100 − (CAP + LRCAP + ASW + 搜索 + 训练 + 休息)
```

推论：
- 打击中队（VB / VT / 被指派攻击任务的 VS）搜索比例设高 = **按比例削掉对舰打击力**；设 100% 则对主任务贡献归零。
- 专职侦察中队设高搜索是本职，但**它不计入打击力**——把两者混算会得出错误的可用打击机数。
- 战斗机 `percent_cap` 高（80~100%）是正常防空配置，其「主任务可用」只剩 20~0%，**这不是异常**。

其它可用字段：`aircraft_active` / `aircraft_max`（机况）、`target_x` / `target_y`（任务目标格，未设时为 0 → 读层导出成 `null`）、
`stationed_on_ship_name`（驻舰名，可据此筛航母舰载队）。

> `target_x/y` 读出为空**只表示该实例未设目标格**，不等于字段不存在。

## 4. 结构里有、但读取器未导出的字段

存档结构定义（`pywitpaescraper/pwsdll.py` 的 `AirGroup` 结构）里还有：

| 字段 | 含义 |
|---|---|
| `range` | **该中队的航程设定**（不是机型的航程）|
| `acRange` | 机型航程（读取器导出为 `aircraft_range`）|
| `targetID` / `targetX` / `targetY` | 任务目标 |
| `acSearchNavStart` / `acSearchNavEnd` | 对海搜索扇区 |

⇒ 问题在导出的 JSON 里答不出时，**先去结构定义确认字段是否存在**，必要时扩读取器；
不要由「JSON 里没有」推出「游戏里没有」。

**★但「扩读取器」不等于「把结构字段名加进输出字典」★**：读取器组装 JSON 的那条路径**不经过原始结构字段名**，
把结构里的字段名（如舰船的 `shipWpnAmmo` / `shipOps`）直接加进输出字典，读出来**全是空数组 / 全 0**，
且**不报错**——看上去像「该字段在存档里就是空的」，实际是根本没取到。
⇒ 要真正导出未导出字段，必须找到**填充该字典的那段解析代码**并在那里接上，不是在外层字典里添键。
⇒ 判据：新增字段若**所有实例一律为 0 / 空**（不是部分为空），先怀疑**取数路径没接上**，而不是数据本身为空。

**★反例（证明「接对了就能导出」）★**：士气 / 经验这两个字段走**正确路径**接上了——
在 `witpae_today.py` 里**填充航空队字典的那一段**（`self._as_int(ag.<字段名>)` 那组赋值）加 `pilotMorale` / `pilotExp`，
**同时**在导出层加对应键，重读后即得真值（实测打击中队 99、侦察中队 74/62、战斗机 44/68）。
⇒ 对照判据：**同一份存档里航空队字段导得出、舰船字段导不出，说明差别不在存档、在解析路径**。
⇒ 只在导出层添键而不改填充段，`dict.get("字段名", -1)` 会**静默返回默认值**（实测返回 `-1`）——
这正是「加进输出字典却全空」的机理。
⇒ 改完必须**强制重读**（`touch` 存档）才看得到新字段，否则拿到的还是上一次解析的产物。

## 5. 编队层（`taskforces.json`）

- 编队任务字段 `mission` 是**名字字符串**（如 `AIRCOMBAT`），不是数字码。航母编队应为 `AIRCOMBAT`。
- 判「这是我方哪一支编队」看 `ships` 舰名 + 编队号；**判「是不是航母编队」必须扫舰名里的 `CV` / `CVL` / `CVE`**，
  不要信 `tactical_group` 标签——引擎会把航母拆成若干护航/分遣编队，标签不再含 CARRIER。
- 目的地真值取 `target_x` / `target_y`（结算后读层为唯一权威）。

---

## 6. 诊断配方：「我方飞机/编队为什么没打」

按顺序读，读完再谈因果：

> **先跑一条命令**：`witp-cmd strike-audit` —— 逐中队打印任务码 / 搜索% / CAP% / **可用机数**，
> 算出每艘航母当回合能投入对海攻击的飞机数（`可用机数 ×（100 − 各项占用）/ 100` 之和），
> 并把读层看不见的硬阻断项（架次 / 天气）单独列出。**它把下面第 2~4 项一次性答完**，
> 剩下的注意力全部留给第 1、5 项。**每回合跑一次**——「航母还在」不等于「航母还能打」。
> 实测两个方向的结论都只有它能给：一局读到合计仅约 **10 架**可出击（两支队鱼雷机 **0/15**），
> 而推进器 / 参谋部 / 读层全都没报警；另一局读到 **52 架**可出击、任务码全对却一架未出。

1. **出击架次** —— 手册点名的**头号硬闸门**（归零则该舰不能执行任何进攻任务），**读层看不见**（见 §4）。
   **游戏内读法**：打开该编队的航空队面板，读 `Carrier Aircraft: 65 (65), MS:414(100%)` ——
   `MS:` 即 Max Sorties 的「当前值 (上限) 与百分比」（手册第 06 章的定义，其举例正是列克星敦 414/414，可作标定基准）。
   **架次归零的表现就是「完好却不出击」，先排这一项。**
2. **编队任务** —— `taskforces.json` 的 `mission`（航母应为 `AIRCOMBAT`）。
3. **中队任务码** —— 每支中队的 `primary_mission_code`（对舰打击应为 `3`）。
4. **分配比例与机况** —— 六项 `percent_*` 算出「可用于主任务的飞机比例」，再乘 `aircraft_active` 得**实际可用机数**；
   某中队 `aircraft_active` 为 0 即该中队飞不了（实测确有中队被打到 **0/15**）。
5. **天气** —— **航空队所在格与目标格**的天气（战报 `Weather in hex:`）；这两格的恶劣天气会让进攻任务
   **起飞前中止**，而**穿越**坏天气格不影响。
6. **士气 / 航程 / 协同** —— 低士气易空中中止（**已可读**：`pilot_morale` / `pilot_exp`，见 §4）；超编队半径不飞；双航母分处异格有协同惩罚。

**★不要把「`target_x/y` 为空」列为候选原因★**：手册 7.2.1.7.1 明确——进攻任务未设目标时由电脑自选，
**只要发现有效敌 TF 就一定发起攻击**（更倾向 5 格内的 TF）。目标格为空**不是**阻断条件。

**未实测连通的项一律标 `unknown`，不得写成结论。**

**受控实验配方**：**载入该回合存档 → 只发一次 `end-turn`（不做任何其它点击）→ 读 `combatreport.txt` 找我方出击段**。
只发一次 `end-turn` 是关键——结算后追加的任何收尾点击都会把结果画面点掉。

**已跑过的受控实验（结果如下，勿重复）**：敌四个水面编队距我航母 **1 / 2 / 4 / 7 格**、
且**全部由我方 SBD 自行发现**，结算后**零空袭**；同回合任务码 3 ✓、可用机 65-73 ✓、
**MS 414(100%)** ✓、**士气 99** ✓。⇒ 架次 / 士气 / 目标自动选择三条**已排除**，**只剩第 5 项（天气）未连通**。

**★排除法只缩小范围，不构成根因★**：
「排除了 N 条候选」≠「找到了原因」。尚未验证的替代解释（例如「被侦测到的编队类型不构成合法打击目标」等）
在实测前同样标 `unknown`，不得拿一条未证实的解释去填满排除后的空位。

## 7. 已知反模式

- ❌ 由中队番号推断任务（番号是默认值，不是事实）。
- ❌ **把 `primary_mission_code = 16`（Training）当成作战任务**：剧本开局大量陆攻 / 战斗机中队处于 Training，
  它们**不会出击**。看到 16 要先判断「这支队本该干什么」，而不是当成已部署。实测两支 27 架零战中队（`Tainan Ku S-1/S-2`）
  整局停在 16，等于全部制空力闲置。
- ❌ **把战略轰炸机 / 陆攻改装去炸地面部队当常规压制手段**：实测 842 架次对守军仅 178 人伤亡、0 个班击毁
  （每架次 0.21 人），且扰乱在回合末被清空（手册 §8.4.5）。软化只认舰炮击 + 地面突击。
  详见 `amphibious-assault-sequence.md`「航空兵在登陆战里的分工」。
- ❌ **把航空兵的主要任务定成「压制守军」而不是「保住登陆船团」**：实测统计「对手空袭的目标分布」，
  **93.5% 打的是水面/运输编队，只有 ~5% 打地面部队、~2% 打基地**。⇒ 登陆战真正的航空任务排序是
  **① 保护卸载海域（CAP/护航）→ ② 打对手水面与航母力量**；把陆攻改去对地属于拿主武器换无效伤害。
  判断依据要读**战报里对手空袭的 target 分类计数**，不要凭「守军难打，那就去炸它」的直觉。
- ❌ 由「工具没有某个子命令」推出「所以任务没被指派」——先读任务码。
- ❌ 把侦察中队的搜索占用算成「被浪费的打击力」；反过来，把打击中队的高搜索比例当成正常。
- ❌ 用 `airgroups.json` 反推哪些编队是航母（巡洋舰也带水侦）——用 `ship_class_type_name` 前缀 `CV`。
- ❌ 用「目标格为空 / 没设目标」解释「飞机为什么没出击」——手册明确未设目标会自动选目标并照打（见 §6）。
- ❌ 只用「航母在不在 / 有没有损伤」判断航母还能不能打——**打击力 = 可用机数 × 未被占用比例**，
  后期两艘航母合计只剩个位数可出击机是常见结局，且**不会自己报警**（每回合跑 `strike-audit`）。
- ❌ 把「排除了 N 条候选」当成「找到了根因」——排除法只缩小范围；空出来的位置要用实测填，不能用推测填。
