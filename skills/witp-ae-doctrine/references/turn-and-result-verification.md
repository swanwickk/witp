> 触发场景：一次结算完之后要判读战果、核验“我的飞机到底出没出击”，或要复现一场已打完对局的终局比分。

# 结算与战果核验（Turn Resolution & Result Verification）

核验铁律：**指令层回读不是真值，唯一权威是结算后的读层与战报**。下面每条都是“怎么拿到真值”的操作法。

## 1. 结算回合：`End the Orders Phase?` 对话框

按 E 提交命令后会弹出 `End the Orders Phase?  YES / NO`，**必须点到 YES 才真正结算**。

- **实测真实坐标（游戏窗口内坐标）：提示文字 y≈380–384；按钮行 y≈428；YES x≈508、NO x≈626。**
- 历史记录里的 YES(696,572) 是**错的**。点了不关框、回合从未结算，症状是：画面长时间不变、战报不更新、**永远等不到终局屏**。
- 症状识别：过回合后画面仍停在命令阶段（顶栏还有 `Forecast / Date / Hex`，中央挂着对话框）——这不是“剧本结束”，是**对话框没关掉**。
- 坐标失配时的通用恢复法：对当前截图做**亮像素行扫描**，找提示文字下方那条按钮行（y≈428 附近），再沿行找按钮中心（得到 ~508 / ~626 两个中心）。**不要照抄历史坐标**——这是对“坐标会漂”的通用解码，不是一次性修坐标。
- 窗口偏移一律用 `witp_sync_offset` 动态取，不写死。

## 2. 终局比分屏：必须主动抢拍

结算完成的那一瞬才弹 `JAPANESE VICTORY LEVEL / FINAL SCORE` 屏。**过回合流程的收尾点击会把它点掉**，于是出现“整局打完却拿不到比分”。

- 纪律：**结算一完成立即截图，之后不做任何点击**。先拿图，再谈收尾。
- 该屏按钮（`View End Game Status` / `Quit Game`）**鼠标点不动，用 Return 键**。
- **该屏不能靠 OCR**（花体+底纹，tesseract 吐乱码）→ 用视觉模型**逐字**读胜负等级与双方分值。
- 分值屏截图**归档**（`endgame_<判定>_<日>_<盟>.png`），并把**真实分值**写进对局归档与台账。
- **拿不到就写“未捕获”，绝不留 0:0 占位**——占位条目会污染跨局统计，比缺数据更糟。
- 已打完的局仍可补分：载入终局存档（`wpae000.pws`）→ 重过最后一回合 → 抢拍。

## 3. 战果判读：谁打了谁、谁沉了

- **作战报告的累计击沉列表只列敌方舰船**（我方战绩）。**我方损失必须另读** `combatreport_<YYMMDD>.txt` 的 `Allied Ships` 段——只读累计列表会**系统性漏报自己的损失**。
- 攻击段归属：段内含 `Japanese Ships` → 该格是**日舰**位置；含 `Allied Ships` → **挨打的是我们**，该格是**我方坐标**，不可反读成敌舰位置。
- **袭击者身份**看 `Japanese aircraft` 名册：`A6M2 Zero + B5N2 Kate + D3A1 Val` = **舰载机**（说明敌航母在打击半径内）；`G3M2 Nell / G4M1 Betty` = **陆基**。据此判断“敌航母是否参战”，不要靠猜。
- **岸炮战果不得记到航空队头上**：舰船在某基地旁被击沉、同段又有该基地炮台的命中记录（`6" Mk XI/XII Gun Battery engaging…`）→ 是**岸炮**打沉的。记成“我方舰载机战果”会凭空虚增成绩。
- `Surface Combat TF nn aborts mission and returns to <port>` = **游戏自行取消了该编队任务**，即“没有发生拦截”的信号。看到它就不要以为水面编队执行了夜战。

## 4. 核验“舰载机到底出没出击”

作战报告**只在真的出击时**才有攻击段。若某日报告里只有侦察/反潜/事故行——

```
Sighting report: N Japanese ships at x,y
SBD-3 Dauntless reports possible submarine / oil slick / turbulence
SBD-3 Dauntless from VS-x is damaged on landing
```

——则**当日零对海攻击**，无论同日侦察报了多少敌情。侦察接触多 ≠ 打过。

- 判据：在当日作战报告里检索攻击段（`Dauntless` / `Devastator` 的 `attacking` 行）；一段都没有 = 打击零出动。
- **侦察纪律（用户订正过，勿再误写）**：航母上**本来就有专职侦察中队（VS）**，它设高搜索是**本职**，不是「把打击力转成侦察兵」。要保打击力，压的是**打击中队（VB / VT）**的搜索比例，不是 VS 的。远程搜索仍应尽量交给 PBY / 陆基。判「某中队贡献多少打击力」只看**任务码 + 搜索比例**，不看番号（见 `carrier-strike-conditions.md` §三）。
- 指纹：终局双航母**完好（系统/进水 0）而战果寥寥** = 打击零出动的典型信号，值得当场追查，不要当成“运气不好”。

## 6. 核验「登陆是否真的发生」（战报字样 ≠ 登陆）

**铁律：`Amphibious TF n unloading at <基地>` 只证明「船在该格」，不证明「船上有部队」。**
两栖登陆的进展必须用**逐舰装载字段**核验，不能用战报字样推定。

- **必查字段（`ships.json` 逐舰）**：`loaded_ground_unit_id` / `loaded_ground_unit_name`。
  **非空才算「带着部队」**；全部为 `None` ⇒ 该编队**此刻**是空船，在目标格卸多久都不会改变归属。
- **反向核验：看部队在不在 `ground_units.json` 名单里**——**已装载的部队不出现在该名单中**
  （它在船上，由 `ships.json` 的 `loaded_ground_unit_*` 承载）。据此可判「是否已卸载上岸」：
  开局不在名单里（在船上）→ 终局出现在名单里（已上岸）。
- **★必须两帧对照，不能只看终局★**：只看终局的「船空载」会把「登陆成功、部队已上岸」
  误判成「从未装载」。对照口径 = **开局帧**（船满载 + 部队不在 `ground_units` 名单）
  与**终局帧**（部队已出现在名单里）两个独立观测。
- **★`at_base_id` 不是位置，不得用它判「部队在哪」，也不得用它否证「已上船」★**
  - 它是部队的**所属 base（编制归属 / 母港）**，**不是「当前所在格」**。
  - 其 id 空间与 `bases.json` 的 `record_id` **不是同一套**：实测 `bases.json` 里 981 = 莫尔兹比港，
    而某方面军司令部 `at_base_id=981` 实际停泊在 Truk (112,108)。**跨表对照会得出荒谬结论。**
  - **位置字段是 `end_of_day_x` / `end_of_day_y`**；是否在船上另看 `loaded_on_ship_id/name`。
  - ⇒ 曾据「部队 `at_base_id` 始终指向母港」推出「从未上船 / 登陆失败」，
    而对照开局与终局两帧后证明登陆**确实发生过**。**该推论是错的，不要再犯。**
- **归属判据不可用「目标基地在不在当回合基地名单里」**：读层 `bases.json` 导出的是**开局归属**的基地
  （开局时敌港本就一个都不在内），**不是当前归属**；且它多半不给 x/y。
  判归属见 SKILL.md §3.6（指挥部名 / `forces CAPTURE` 战报行），不要用名单缺席做推断。
- **判定登陆进展的三步（全为正面观测，缺一即不得写「登陆进行中 / 登陆失败」）**：
  1. 逐舰 `loaded_ground_unit_id` 非空（兵力确实在船上）；
  2. 该部队不在 `ground_units.json` 名单里（确实已上船）；
  3. 战报 / 地面战段里出现**攻方兵力行**（确实已上岸）。
  攻占与否另用 §7 的「`forces CAPTURE <基地>`」判，**不可用战报缺席反推**。
- **配套（何时算「窗口已关」）**：看**敌方上岸兵力是否停止增长**，不看击沉数；
  地面战行的 `Defending force` / `Attacking force` 出现前还有两个更早的信号：
  `Amphibious Assault at <基地名>` 与 `troops unloading over beach`，两者出现更早。
- **与 SKILL.md 一级铁律的关系**：**只有「卸载成功改变归属」才产生胜负效果**——
  这是「胜负点归属是唯一评分关键」在登陆方向上的直接推论。
  抢着报告「我们已经登陆了」而未查装载字段，等于把假进展写进后续推理。

## 5. 能力边界：任务下发（`set-mission` 已存在）

`witp-cmd set-mission --group <中队> --mission <任务名>` **已建成并实机跑通**（番号与任务解耦；路径、任务箭头坐标表与**当前验证状态**见 `carrier-strike-conditions.md` §七）。
⇒ **不得再把「工具链没有 `set-mission`、所以任务没设上」当作任何失败的归因** —— 该缺口已闭合。

- 其余相关命令：`set-dest`（航向）/ `set-cap`（CAP 比例）/ `set-search`（搜索比例）/ `strike-audit`（逐中队核算可出击数）。
- 通则：**打航母、打登陆船团这类策略，若落不到操作层就等于没有这条策略**；新策略入库时必须同时给出发起点（哪条命令、哪个控件），并核实该命令**当前验证到哪一步**——**能开屏 ≠ 能把值改对**。

## 7. 断言「某事件未发生」之前，先证明查过**承载该事件的那个文件**

**铁律：`A 文件里没有` ≠ `事件没发生`。** 每类事件只写在特定文件里；查错文件得到的是
**自信的假否定结论**，且不报错。

| 事件 | 写在哪个文件 | 不在哪个文件 |
|---|---|---|
| **地面战 / 基地攻占**（`forces CAPTURE <基地> !!!`、`Attacking/Defending force`、`Shock/Deliberate attack`） | `combatreport_<YYMMDD>.txt`、`aoperationsreport_<YYMMDD>.txt`、`joperationsreport_<YYMMDD>.txt` | **`Combat_Events_<YYMMDD>.txt`** —— 它只有**阶段流水**（`NAVAL MOVEMENT PHASE` / `AIR STRIKES` / `AIRCRAFT LANDING` / `REPAIRING SHIPS` …） |
| 我方舰载机出击段 | `combatreport_*` 的攻击段 | 同上 |
| 回合是否结算 | `combatreport.txt` 非 0 字节 + 含 `AFTER ACTION REPORTS FOR <日期>` | — |
| 终局比分 | 存档 `SCENINFO` 的 `japanVP`/`alliedVP`（见 SKILL.md §3.5） | 不必抢拍结算屏 |
| **目标基地当前归谁（己方为日军时）** | `combatreport_*` 地面战段的 `Assaulting units` / `Defending units` 名单（**攻守方互换 = 已易手**） | 我方基地名单（日军侧实测压根不含该基地，列表法无从比） |

- **★「地面战 / 攻占」必须在带日期的战报里查，`*operationsreport.txt`（无日期后缀者）往往只是最后一日的快照★**：
  该无后缀文件被逐日覆盖，某日读到的内容在后续回合已不存在。要看攻占与地面战序列，
  必须遍历 `combatreport_<YYMMDD>.txt` / `*operationsreport_<YYMMDD>.txt` 全序列。
- **判断目标基地归属，`Assaulting` / `Defending` 名单比「基地名单成员资格」可靠**：
  前者不受侧过滤影响（战报里攻守双方都列名），后者在己方为日军时会因该基地不存在于我方名单而完全失效。
- **自己的基地归谁，用正观测算：己方地面部队 / 航空队的 `end_of_day_x/y` 落在哪个基地坐标上，该基地即为己方所有**。
  这是唯一不受「名单反映开局归属」缺陷影响的己方基地判据，且数据就在读层里。

- **`Combat_Events_*` 是「阶段清单」不是「战果清单」**：它里面 `AIR STRIKES` 段后为空，
  只能说明**该阶段无空袭**，**绝不能**据此说「没打地面战」——地面战本就不写在这个文件里。
- ⇒ 写任何「全程未发生 X」的结论前，先问一句：**「承载 X 的文件我查了吗？」**
  查过再写；没查过就写「未核，不作结论」。
- ⇒ 同理适用于**跨局**：存档与 SAVE 目录被多局共用，**开新局会清掉上一局全部战报**。
  上一局的战报一旦被清，任何关于上一局战果的复查都**不可追溯**——此时如实写「不可追溯」，
  **不得用「没有证据表明发生过」反推为「没发生」**，也不得据此写进 SKB 教条。
