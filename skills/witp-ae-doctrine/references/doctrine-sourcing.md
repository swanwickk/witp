# WitP-AE 作战方略：信息源清单与查证方法

供 SKILL.md 第三节「情报查证纪律」配套使用。**只在需要外部调研时读本文件。**

---

## 一、权威信息源

### 1.1 官方手册（最高优先级）
技能 `witp-ae-manual` 已内含章节化手册正文。机制类问题**先查它**，重点是：
- `chapters/06-naval-units.md` —— 6.2.4 Patrol/Retreat 与 Max React Range；6.2.5 各任务类型对移动的影响；6.3.4 航母编队特殊移动（反应距离按格数分档）；6.2.7 指定目的地
- `chapters/07-air-units.md` —— 7.2 搜索与扇面（10 度扇区分配机制）；7.2.1 LRCAP 效率（对航母 TF 仅 20%）；7.2.1.11 协通惩罚阈值公式；7.2.1.12 天气中断；7.2.1.13 任务限制（尺寸 1 机场不能起飞攻击任务）
- `chapters/17-victory-conditions.md` —— 胜利等级判定比例（1.25 / 1.75 倍分界）
- `cheatsheet.md` / `patterns.md` —— 速查表与 SOP

### 1.2 Matrix Games 官方论坛（WitP-AE 分版）
社区主战场。**检索方式**：把 `site:forums.matrixgames.com` 与具体机制词组合，比泛搜命中率高得多。

**值得优先检索的帖子类型**：
- 标题为 `walk through` / `newbie tutorial` / `AAR` 的成套打法帖
- 标题直接是机制词的帖：`Remain on Station`、`CAP strategy`、`Attack Bombers`、`Dive bombing altitudes`、`Allied carrier task force`、`Allied CVs, early war`

**识别高价值回帖者**：帖数数千至上万、答复成体系、解释机制而非只给结论。读帖时**先看作者帖数与历史，再判断该结论的权重**。

### 1.3 社区 wiki
WitP-AE 的 Fandom wiki 有 `Naval_Tactics` 等战术页，机制描述质量高（巡逻区设定、母港方向、反应距离分档、反应可多次触发）。

**⚠️ 该站有机器人防护**：直接抓取常返回校验页。**补救方法**：用搜索引擎检索该页特有的句子片段，结果摘要会直接带出原文段落；对多个片段分别检索即可拼出要点。**报告中须标注「未取得全文，完整性存疑」。**

### 1.4 Reddit r/computerwargames
以「去哪里找资料」的指路性回复为主，机制细节少。可用于确认社区共识的**存在性**，不适合作为机制依据。

## 二、查证流程

```
① 用机制关键词 + site: 限定检索论坛
② 命中官方手册已有条款 → 直接引手册，跳过社区
③ 社区独有结论 → 查该结论是否与手册数值冲突 → 冲突则打折并标注理由
④ 与己方台账对照 → 分类为「一致 / 本机更优 / 本机空白」
⑤ 只把「本机空白」项写进下一局执行清单
⑥ 拟入 SKB 的条目列候选清单待批
```

**关键纪律**：第 ③ 步不可省。社区建议常常**在特定编组/年份成立、被无限泛化**（例如把「盟军 1944 年的航母使用法」套到 1942 年珊瑚海）。

## 五、本机读层字段速查（实证）

- **编队** `taskforces.json`：标识用 `record_id`（= 游戏内 TF 编号），显示名用 `flagship_name`；**无 `id`/`name` 字段**；位置/目标用 `start_of_day_x/y`、`end_of_day_x/y`、`target_x/y`。
- **航空队** `airgroups.json`：标识 `record_id` + `name`（可能为空，空的不可执行须跳过）；CAP 比例 `percent_cap`，任务码 `primary_mission_code`（1=Airfield、3=Naval Attack、6=Escort/CAP、8=Naval Search、9=ASW）；扇面 `search_arc_start/end`。
  - **避坑准则**：`percent_cap` 仅对战斗机（VF）有效。俯冲轰炸机（VB/VS）、鱼雷机（VT）等任务码为 3 的攻击机，前端与参谋指令严禁出现 `SET_CAP_PERCENT`（即使是 0% 也是错误的业务指代）；攻击机的战术调整应是协同高度（10,000 ft）或攻击目标。
- **情报** `threats.json`：载荷为 `position: {x,y}` + `sample_texts`。
- **基地** `bases.json`：`airfield` / `airfield_damage` / `port` / `supply` / `fuel` / `stationed_air_names` / `stationed_ground_names`。
- **⚠️ 读层看不到本回合刚下的指令**：目的地/任务等指令在结算前只存在于内存，存档文件里仍是旧值。因此结算前 `taskforces.json` 的 `target_x/y` 不会随 `set-dest` 改变——**「读层没变」不等于「指令没生效」**。即时确认只能靠界面回读；最终确认靠**结算后**读层。

## 六、参谋推演呈现与指令下发规范（业务语义避坑）

1. **实时自动更新与数据源锁定**：
   - **方案实时自动推送**：方案必须由参谋工具（监听器/读层）在检测到新回合/新存档后自动推送给 LLM 实时出具，禁止让用户手动重复点击。前端建立静默轮询，无感更新。
   - **严格锁定当前正在玩的活跃存档**：后端默认必须锁定 `wpae000.pws`（Autosave / 结算后新状态），严禁读取旧快照或上回合 PreTurnSave。
   - **界面不得展示数据来源存档**：用户端推演界面完全隐藏“数据来源存档：wpae00X.pws”字样与底层技术端口号（如 18090），避免暴露底层调试信息，直接展示当前激活生效的参谋大模型。

2. **威胁分级去通货膨胀与情报中文化**：
   - 严禁将所有目击情报一律标为红色高危，必须分级：
     ① 🔴 **即刻危机（Critical）**：我方舰队被敌机跟踪定位（Shadowed）、敌登陆突击与近距交战、敌航母近距接触；
     ② 🟡 **重点监控（Major）**：敌主力水面舰队调动、集结编队；
     ③ 🟢 **常规警戒（Routine）**：远距离辅助舰艇报告、潜艇目击、单次无线电信号截获。
   - 严禁直接在界面堆叠原始英文 Combat Report 片段，必须清洗提炼为中文战术情报（舰种、数量、航向、航速、距我方相对距离）。

3. **兵力战备与核心意图层次化**：
   - 推演方案顶部必须展示我方主力双航母当前坐标阵位与舰载机战备完好数（战斗机 CAP / 攻击机总数），意图必须基于实际兵力。
   - 战略意图严禁堆砌长篇“八股文”和教条编号，必须按主要矛盾和分点呈现；「海空搜索重点」必须作为一级模块独立高亮展示。

4. **指令分块与可审查性**：
   - 推荐行动表格按部队战术群（航母打击群、水面与后勤、前哨潜艇、防空制空）分类，支持按群快速筛选。
   - 动作和参数全面语义化，优先级区分「必选避险/战术突击/防空顶格/后撤疏散」。
   - 严禁给非战斗机（VB/VS/VT 等攻击机）分配 `SET_CAP_PERCENT`（即使是 0% 也是错误的业务指代）。
   - 前线执行指令不得用单行巨长 `&&` 混杂到底；必须分段（航线指令、防空指令、全套指令）展示并提供独立复制，支持分步审查。
