# 敌情解析：把「我方行动」误读成「敌情」的三类坑

参谋部曾输出「敌航母目击 (13,42) → 建议打击位 (17,44)」，而那是**距我方航母 139 格、完全在地图外**的坐标。
任何从战报/日志抽取接触点的代码，都必须过下面的闸门。

## 1. 坐标正则：绝不能抓区块里「第一个数字,数字」

**机制**：`re.search(r"(\d{2,3})\s*,\s*(\d{2,3})", blk)` 会把区块里最先出现的「数字,数字」当坐标，
于是 `altitude 18,000 feet` → `(18,0)`、炮战 `7,000 yards` → `(7,0)` 之类全被当成 hex。

**规则**：
- **只从标题行取坐标**，且必须形如 ` at HH,HH`（WitP-AE 标题写法：`Air attack on TF, near X at 113,134`）。
  区块正文里的数字（高度/码数/航速/时间）一律不参与坐标匹配。
- 再加 **数值合理性闸门**（0..199）与**调用方传入的地图包围盒**闸门（包围盒由当回合读层的基地/舰船坐标算出，**不得硬编码剧本地名或范围**）。

## 2. 敌情归属：先证明「是敌方在飞」

**机制**：只要区块里出现舰载机型号就判「敌航母线索」，会把**我方反潜/侦察**读成敌情：
`SBD-3 Dauntless from VS-5 attacking a Type KD7 class SS at ...` 被判成敌航母目击。

**规则**：判为敌情前，**必须先满足区块内含 `Japanese aircraft`**（即真是日机在飞）。
我机打击日舰的区块只说明「该格有日方目标」，**不构成敌航母线索**。

## 3. 时效：旧战报不是现情报

扫描「近 N 个游戏日」的归档战报（`aoperationsreport_YYMMDD.txt` / `combatreport_YYMMDD.txt`）会把
**上一回合甚至上一局**的接触点算进当前局面。

**规则**：
- 开新局先清**全部**战报（含无日期后缀者），否则旧接触点会持续污染判断。
- **接触点与当回合读层兵力状态自相矛盾时，先怀疑来源过期**，再怀疑解析逻辑。

## 验证口径（修复必须按这个验）

同一局面，修复前 `detected=True` + 伪坐标；修复后应为 **`detected=False` / 「未发现日军舰载攻击机活动」**，
参谋部结论随之改为「本回合无敌航母情报——无目击证据不作猜测」。
全文再 grep 一次伪坐标与「距我 N 格」式数字，**必须为 0 处**才算修完。

## 通用规则（可迁移到任何情报解析器）

**情报解析器的输出必须过「物理合理性」闸门**——在地图范围内、目标单位确实存在于读层、来源在时效内。
只过语法解析（正则能匹配）就发布情报，必然产出自信的垃圾。
