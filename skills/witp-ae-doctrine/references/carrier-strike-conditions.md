# 航母出击条件核查（Carrier Strike Conditions）

用于两类判断：①「航母为什么不出击」的归因；②核算某回合航母实际可出动的打击力。

## 一、先做核查表，再谈根因

**在「航母不出击」的任何结论成立之前，必须逐项核实手册 ch.07 的全部出击条件。配置全绿而仍不出击时，结论只能是「原因落在尚未读到的那一项内」，严禁指名某个机制。**

| 条件 | 手册条 | 怎么读 |
|---|---|---|
| 编队任务 = 空战（AIRCOMBAT） | — | 读层 `taskforces.json` |
| 中队主任务 = Naval Attack | 7.2.1 | 读层 `primary_mission_code`；界面按 `N` 的 Mission 列 |
| 出击架次 Max Sorties > 0 | 7.2.1.10.1 | **只在游戏内可读**：`T` 列表打开航母编队，屏上 `MS:414(100%)`。读层不导出架次 |
| 士气 | 7.2.1.4 | 读层 `airgroups` 的 `pilot_morale` / `pilot_exp`（已实测导出；实测打击中队士气可达 99） |
| 可用机 > 0 | — | 读层 `airgroups` ready 数 |
| 引擎**确实给该中队排了任务** | — | `N` 列表的 **`Mi`（出击次数）列**：整局恒为 0 即「引擎从未给它排过任务」。这是「不出击」的**直接观测值**，不是推断 |
| 该中队**确实在编**（不是碎片） | — | 读层列出该航母上**全部**航空队条目（**含同名重复**）：曾实测同名出现两条（一条 9 架碎片挂在另一艘航母上）。碎片不是主队，主队的任务字段管不到它 |
| 目标 | 7.2.1.7.1 | 界面 `Commander Discretion` = 自动选目标；手册明言自动选目标时「有已发现的有效 TF 就一定发起攻击」 |
| 射程覆盖目标 | 7.2.1.6 | 详情屏 `Normal Radius`（SBD = 7 格 / 250 海里）。**⚠️ 读层里长得像「射程」的字段是机型航程，不是中队的半径设定**——拿它当半径会把「超半径所以不飞」这个候选原因算错 |
| 敌情：有**有效的**已发现 TF | 7.2.1.7.1 | 战报 sighting 行。接触到的若是潜艇 / 巡逻 / 反潜编队，可能不构成「有效 TF」——**未坐实的次强候选**（实测我方 SBD 在航母旁报 `periscope wake` / `conning tower`，同回合零出击）。**先排 CAP/护航（§一之二 候选 5），再查本项** |
| 天气：本格与目标格非坏天气 | 7.2.1.12 / ch.12 | 读层无天气字段。**等级序（手册 ch.12）**：Clear → Partly Cloudy → **Overcast** → Rain → Thunderstorms ⇒ **`Overcast` 是中间等级、不属坏天气**，不要把它当阻断项（顶栏常年显示 Overcast 时不要据此判「天气挡住了」）。天气**按「象限」生成**，顶栏 `Forecast` 显示**当前格**的预报 ⇒ 它**能分辨象限、不能分辨相邻格**（实测换多个位置读数不变，与「同象限共享」一致）。**逐格判断只能看地图云图标**，而开云图标**不必进偏好屏：`F7` 即热键**（工具条与偏好开关坐标见 `witp-ae-interface/references/ops-log.md`）。**已实测：把地图滚到航母所在格（顶栏 Hex 读数确认落格）后，该格周边无任何云图标 ⇒ 该处非坏天气。** 但「无云图标 ⇔ 非坏天气」这个等价本身**尚未独立验证**（地图可能未即时重绘、或云只对某些天气等级渲染），故只作**弱证据** |

**坑（最重要）**：不要在核完之前写下「根因是 X」的教条。错误因果一旦入库就是智力污染，而且会被后续回合反复引用。本技能已有出击归因被实证推翻的先例 —— 遇到这种情况**就地改正原句**，不要在其下追加「更正：其实……」段落。

**坑**：读层不是全知。架次、逐格天气、中队射程设定这三项读层都没有，必须回游戏界面读。把「读层里没有」误当成「该项正常」会得出完全相反的结论。

### 一之二、已实测的「全绿却零出击」样本（用它做排除，不要重复劳动）

某局实测：编队任务 AIRCOMBAT ✓、六支打击中队主任务码 3 ✓、可用机 65–73/73 ✓、`MS:414(100%)` ✓、
打击中队士气 99 ✓、经验 79–84 ✓、疲劳 0 ✓、敌水面编队由**我方 SBD 自己发现**且位于距航母 **1 / 2 / 4 / 7 格** ✓
—— 结算后战报**零空袭**（当日日军亦仅一次对地攻击）。

其中**决定性的一条**是 `N` 列表 VB-2 行的 **`Mi`（出击次数）= 0**：一艘参战航母上的俯冲轰炸中队，
12 天战事里一次任务都没飞过；而同屏 VS-2 / VS-5 有持续出动（战报里的 sighting 行就出自它们）。
⇒ 这条读数把问题从「打不出去」精确定位到「**引擎根本没给它排任务**」，并一次性排除
「打累了 / 士气低 / 没飞机 / 架次耗尽」四类解释（疲劳 0、士气 99、可用 17、架次满）。

**`N` 列表列位（实测 x）**：Num 534 / Exp 559 / Fat 584 / **Mi 600** / Morale 614 / Mission 670 / Patrol 714 / Location 776。
`Mi` 与 `Fat` 为 0 时**显示为空**，不要当成「读不到」。

**剩余候选（全部标 `unknown`，未实测连通前不得写成结论）**：
1. **接触到的不是「有效 TF」**（手册原文的「有效」二字）—— 战报里那些编队只有 4–7 艘、航速 11–13 节，
   同日我方 SBD 就在航母旁报 `periscope wake` / `conning tower`（日方潜艇确在附近）。**唯一仍在的候选。**
2. ~~**中队在引擎内部「未就位」**（碎片 / fragment）~~ ⇒ **★已排除★**：读层已全量列出两艘航母上的航空队条目，
   **恰好 8 条、一一对应、无任何同名重复**，`rec_id` 连续且分别挂在正确的航母上（各舰 VF/VS/VB/VT 各一条）。
   主队确在编 ⇒ **碎片假设作废，不要再查**。
3. ~~**航母编队自身状态**（目的地 `nearto` / 「移动中」）~~ ⇒ **★已实测且无变化（部分排除）★**：把一艘航母编队的
   目的地设为**它自己所在的格**（回执确认目的地列收敛到该格）后过回合，**仍然零出击**。
   **只算部分排除**：同回合另一艘航母的目的地未能确认生效（结算时它出现在别的格 ⇒ 仍在移动），
   故只记「已测的那一艘不成立」，**不得写成整条候选已排除**。
4. **编队指令被引擎重置为「返回母港」⇒ 任务中止 ⇒ 不发起打击**（手册 §6.2.9 + 社区机制，**未坐实**）。
   手册 §6.2.9「编队返回母港」条件清单里含「**编队内已无航母能起飞飞机**」与「**巡逻-撤退状态不是 `Remain on Station`**」；
   社区（Matrix 官方论坛《Remain on Station》帖）补充：**ROS 本身不阻止反应，但若同时设了反应距离，一旦真的反应，
   该动作会把 ROS 重置为「返回母港」**；想「原地待机 + 保留反应」应改用**单格巡逻区**。
   凡「编队返回母港」即任务中止，而中止的编队不发起打击。
   **为何仍未坐实**：进游戏读两舰目的地，仍是 `nearto 97,145 / 99,145`，**并未重置为母港**。
   ⇒ **但目的地 ≠ 巡逻/撤退状态**（详情屏上两个不同字段），故本条**不得据此判为已排除**，
   只能记为「**机制候选，待读巡逻/撤退字段坐实**」。**在读到该字段前，不得把本条写成结论。**

5. **★已定案：护航兵力不足 ⇒ 指挥官不批准出击（CAP 吃掉护航）★**（手册 7.2.1.7.1：「若该单位可用护航兵力
   不足以对抗目标处预期敌 CAP，则该目标被选中的概率下降」）。**这是「全绿却零出击」的第一性原因。**
   **单变量实测对照**：珊瑚海剧本两局**唯一差异是 CAP 百分比**——
   `VF CAP 80%` 的那局 **12 个回合零出击段**；`CAP 40%` 的那局**第 1 回合即 3 次对海攻击**，
   **4 回合合计 14 次出击段 / 6 次对海攻击**（SBD 俯冲 + TBD 投雷；打击点 Rekata Bay / Tulagi /
   Deboyne Islands 103,134 与 106,142 / Rennell Island 111,140），其中 `T3 = 0` 系当回合无敌情接触。
   ⇒ **标准动作：双航母开局即设 `CAP 40%`**；敌航母已定位且逼近时临时回补，回补后重跑 `strike-audit`。
   ⇒ **教训（写进方法，不写进结论）**：本条曾被「正向对照局」否证过一次——理由是「前一局同为 CAP 80%，
   却打沉了敌航母」。**那次否证是错的**：两局的编队任务 / 巡逻撤退字段 / 指令来源同时不同，
   **不是单变量对照**，故那次对照既不能证实也不能证伪，只能搁置。
   ⇒ **通用判据：排除候选靠对照局，但对照必须「同剧本、同配置、单变量」**；变量不止一个时不得下结论。

**⇒ 诊断顺序（两条候选都属「编队层」，应在查下一个条件之前先排掉）**：编队巡逻/撤退字段是否已变成「返回母港」
→ 架次 → 天气 → 目标 → 中队任务。**中队任务与架次是最容易被误判的两项**（界面 Mission 列与读层任务码应当先互证，
别一上来就怀疑「任务没设」——这个归因已被实证推翻过一次）。

**★新判据：逐中队对照「作战报告里的实际活动」与「该中队的分配百分比」★**（最有分辨力的一条）
同一回合实测：**VS-2 / VS-5（搜索 100%）** 在作战报告里大量 `sighting report`；**VF-2 / VF-5（CAP 80%）**
起飞拦截并有降落损毁；而 **VB-2 / VB-5（搜索 20%）与 VT-2 / VT-5（搜索 0%）在作战报告里一行都没有**。
⇒ **带非零百分比的中队（搜索 / CAP）都在飞；百分比为 0–20 的中队一次都不飞。**
⇒ 即**辅助任务正常、主任务（Naval Attack）根本没有被执行**；这与 `Mi = 0` 互为独立观测。
⇒ 用法：**排查「零出击」时先按中队逐个查作战报告**（哪些飞了、哪些一行都没有），比继续逐项核条件闸门更快定位；
**条件全绿却零出击，优先怀疑「主任务未被引擎执行」。**

**同回合的另一条事实**：**我方航母自己被日军舰载机打了**（战报 `Air attack on TF`，日机含 `B5N2 Kate`，
我方 CAP 起飞拦截、中 1 弹）⇒ **双方已在互相的打击半径内，敌航母确在附近**，
「够不着 / 没目标」这一解释也被排除。

**★「显式指定目标格」已被规则封死，不要再试★**：手册 7.2.1.7.1 明言
**对海攻击任务的中队，目标选择始终由电脑控制；给它设目标只作用于副任务**。
实测完全吻合：点详情屏 `Select Target` 会**关闭详情屏进入「在地图上点选目标格」模式**，但在该模式下点地图
**未能设置目标**（重新开屏回读 `Target:` 仍为 `Commander Discretion`），且顶栏 `Hex` 读数停更。
⇒ 这是**设计如此，不是控件没摸清**。**「显式指定目标格」不得再列为候选原因、也不得再列为待补的能力缺口**；
不要再为它实现 `set-target` 之类的命令。
（注意区分：`set-mission` 改的是**任务**，不是**目标格**。）

## 二、任务码映射（界面与手册双重证实）

```
1 = Airfield（对机场）      3 = Naval Attack（对海攻击）
6 = Escort / CAP            8 = Naval Search（对海搜索）
9 = ASW（反潜）
```

验证法：`A` 列表看陆基（B-25C 显示 `Airfield` → 码 1）、`N` 列表看舰载（VF 显示 `Escort` → 码 6），两处与读层字段对照。**码表只认界面/手册双重确认，不认推断。**

## 三、中队番号 ≠ 任务（用户订正过）

VF / VB / VS / VT 只是历史番号，**任务可自由指派，不跟着番号走**。

- VS = 侦察中队，100% 搜索是它的本职，**不是「吃掉一半打击力」**。
- 判断某中队是否贡献打击力，看**任务码 + 搜索比例**，不看番号。
- 算式：`可出击数 = 可用机 × (100 − CAP/LRCAP/ASW/搜索/训练/休息 占用%)`。搜索比例直接吞掉同比例的打击力。

## 四、架次（Sorties）是必须主动管理的硬资源

- CAP 与搜索**不**耗架次；出击与护航**耗**架次。
- 手册 ch.06 以 Lexington 414/414 为例说明满架次量级 —— 屏上 `MS:414(100%)` 即满。
- **打残即撤**：逐回合记航母可用打击力，掉到阈值以下就脱离去补给，不要留在原地空转。

## 五、可用工具

```
witp-cmd strike-audit [--state <state目录>]
```

逐中队列 mission code / 搜索% / CAP% / 可用机，汇总每艘航母的可出击数，并列出不可见的硬阻断项。**每回合过回合前跑一次**，与上一回合对比，才能在「打残」发生的当回合看出来。

## 六、航空队详情屏（读读层没有的字段的地方）

入口：`N` 列表 → 点目标中队行 → 详情屏。屏上分两组：

- **左列 = 主任务列表**，高亮项即当前主任务；**右列 = 副任务列表**，高亮项即当前副任务（对应读层 `secondary_mission_code`）。
- `Target:` 行 —— `Commander Discretion`（自动）或 `Select Target`。
  **⚠️ 对海攻击任务的中队，目标由电脑控制，设不了（手册 7.2.1.7.1）**：点它（实测 ≈(698,287)，左侧箭头 ≈(653,286)）
  会**关闭详情屏**、进入「在地图上点选目标格」模式，但该模式下点地图**未能设置目标**
  （重开屏回读仍 `Commander Discretion`），且顶栏 `Hex` 读数停更。**这是设计如此，不是控件没摸清——不要再试。**
- `Normal Radius` / `Extended Radius` / `Maximum Range`。
- `Serviceable` 可用机数。

**坑**：任务列表的高亮项**只能靠视觉读屏**判断 —— OCR 只给文字与坐标，给不出「哪一项被高亮」。用 OCR 的列表输出推断当前任务会出错。

## 七、任务指派：`witp-cmd set-mission`

```
witp-cmd set-mission --group VT-2 --mission "Naval Attack"
```

番号与任务解耦（见 §三），所以任务必须能改；这条命令就是改它的手段。

**路径**：先点地图取焦 → 发 `N` 开舰载航空队列表 → OCR 定位该中队行 → 点开详情屏 → 点任务列表左侧的箭头。

**任务箭头坐标**：`x=653`，`y` = 任务文本行 y − 5。

| 任务 | y | 任务 | y |
|---|---|---|---|
| Airfield Attack | 144 | Naval Search | 203 |
| Port Attack | 155 | ASW Patrol | 215 |
| Naval Attack | 167 | Supply Transport | 226 |
| Ground Attack | 179 | City Attack | 239 |
| Recon | 191 | Training / Stand Down | 251 / 263 |

（详情屏任务文本首行 y≈148、行距 12px；上表与既有笔记里的箭头坐标一致，两源互证。）

**⚠️ 验证状态（务必先读）**：**「列表 → 行 → 详情屏 → 点箭头」这条路径已实机验证**（能正确命中目标中队并开屏）。
但**「点 (653, y) 真的把任务改成了目标值」尚未取得回执** —— 当时发的是 no-op（目标中队本来就已是该任务），
且回读 OCR 未能识别任务文字。**首次用本命令做真实变更时，必须自己补一次「改 → 详情屏人工核对 → 改回」的往返验证**，
不要假定上表一定对。任务列表的 y 会随屏内容位移，上表若失效，先重新扫描任务列表文字行再推算箭头 y。

**坑（实体名匹配）**：舰载航空队列表的 OCR 会把 `VT-2` 读成 **`NT-2`**（V↔N 字形混淆，与 V↔Y 同类）。
匹配必须做**字形归一**（N/Y → V）**并要求唯一命中**，多命中一律拒收 —— 宁可失败也不改错部队（见 SKILL.md §5.8）。

**坑（热键）**：`N` / `A` / `T` 需要地图先有焦点。发完热键**必须验证面板真的开了**：
OCR 词数 ≈50 = 没开（仍在地图），≈300 = 开了。没开就点一下地图再重发，不要在没开的屏上继续点坐标。

**回读限制**：详情屏任务文字的 OCR 尚不能稳定识别，**不要拿回读当成功回执**；
最终仍以详情屏人工核对、或结算后读层 `primary_mission_code` 为准。

## 八、机制未定案时的对策（别让推演停在谜题上）

「主任务不执行」的机制层**主因已定案**：**CAP 吃掉护航 ⇒ 指挥官不批准出击**（§一之二 候选 5，单变量实测）。
剩余未坐实的候选只有两条：「接触到的不是有效 TF」、「编队指令被重置为返回母港 ⇒ 任务中止」。
**作战对策不依赖剩余候选**，固定三条：

1. **陆基航空队承担 PM 方向的近距掠桅打击**（舰载机在 `CAP 40%` 下已能出击，不再是「唯一」手段）——
   B-17 / A-20 / B-25 等改 Naval Attack；攻击型轰炸机高度设 ≤6,000 ft 会触发自动掠桅（SKILL.md 铁律 M）。
2. **舰载机保留搜索与 CAP 职能**——这两项实测可靠（VS 的 sighting 行、VF 的拦截都真实出现在战报里）；
   不要为「凑打击力」去压 VS 的搜索比例。
3. **每回合两道自动核验**：过回合前 `strike-audit`，过回合后核 `combatreport.txt` 有无我方出击段
   （按 `-`×40 切块、含 `Allied aircraft` 且不含 `no flights` 即出击段；零出击段必须告警）。

⇒ **原因标 `unknown`、对策照常确定**——把「不确定的因果」与「已确定的应对」分开写，
既能继续推进推演，又不会把猜测污染成教条。
