## 二、内存路线的实测障碍

### 反汇编已定位到的运行时结构（供后人参考）

| 步长 | 基址（VA） | 含义 |
|---|---|---|
| `0x494`(1172) | `0x4570c7a` | Location 结构数组 |
| `0x1d0`(464) | `0x1a144c2` | 一种 TF 结构（464B） |
| `0x22c`(556) | `0x6da52ca6` | 另一种 TF 结构（556B，与存档同尺寸） |

这些来自 `0x640100` 附近的函数，典型指令：

```
640150: movswl -0xae8(%ebp),%ecx
640157: imul   $0x1d0,%ecx,%ecx
64015d: movb   $0x63,0x1a144c2(%ecx)     ; 写 0x63=99
```

### 为什么读不到

- 这三个地址都在 wine 32 位堆区（`0x12d12000-0x15c50000` 等 rwxp 段）
- `gdb` 能读能写（写入 `0x41424344` 后能读回），但**读出来全是 0**
- 说明这些是 `.bss` 段地址，实际数据在**重定位后**的别处，或该结构当前未被使用

### 存档特征在内存里搜不到

用存档里的真实值做特征串扫描，全部 0 命中：

| 特征 | 结果 |
|---|---|
| `flagship=6 + home=471`（TF1） | 命中 0 |
| TF1 的 4 个连续航路点 | 命中 0 |
| `flagship=3002`（TF14） | 命中 167 处，全是数值巧合（附近无 home=1282） |

⇒ 运行时数据经过**完整转换**，与存档没有字节级对应关系。

## 三、Retirement 已用界面闭环实现（可用）

不依赖存档，走 VNC 点击 + OCR 判读：

```python
import gui_commands
gui_commands.set_retirement(7, 'allowed')   # -> (True, 'allowed')
gui_commands.set_retirement(7, 'remain')    # -> (True, 'remain')
```

**判据是 OCR 文字匹配**（不是颜色计数）：

- 截图区域 `(355,270)-(500,296)`，放大 4 倍，`tesseract --psm 6`
- `Retirement Allowed` → 含 `allow`
- `Remain on Station` → 含 `remain` / `station`

点击位置：**y=288**（状态值行），x=400。

> 教训：早期用"黄色像素数量"做判据，`allowed` 和 `remain` 的计数会互相翻转，
> 导致误判。OCR 文本匹配才可靠。

## 五之二、本轮新增的实测结果

### 运行时 TF 结构已定位（重要）

反汇编找到三套并存的结构：

| 步长 | 基址（实际可读） | 含义 |
|---|---|---|
| `0x1d0`(464) | **`0x1a14ae0`** | TF 结构，slot0=TF1(Shikaku) |
| `0x494`(1172) | `0x4570c7a` | Location 结构 |
| `0x22c`(556) | — | 另一 TF 数组（未确认） |

**`0x1a14ae0` 是实测能读到的**（`0x1a14000` 是错的，偏 0xAE0）。
slot 0..29 对应 TF1..TF30，off 424.. 是编队名 ASCII。

### 但 Retirement 不在其中

抓到 `0x1a14ae0` 前后各 2MB（共 4MB），切换 Retirement 前后各 dump 一次：

```
差异字节数: 0
```

**4MB 范围内零差异。** 说明 Retirement 存在 UI 层缓存，
或根本不持久化在可写的游戏数据区。

### 目的地清除已打通（Patrol Zone 前置）

`witp_clear_tf_destination` 实测有效：

```
Set TF Destination
Destination Hex: 99,127   →   Destination Hex: None
```

做法：点 Set TF Destination(533,200) 进选格模式 → 地图右键取消。

清空后 Routing 子面板的 `Set Patrol Zone` 从
"not available when destination is set" 变为**可用**（已验证界面文字变化）。

但点击 `Set Patrol Zone`（180,382）仍未进入选格模式——
该行可能只对"海上、非停泊"的编队可点。

## 六、如果继续，最该做的两件事

1. **给 exe 打补丁**：`0x640250` 是"显示单个 TF 的 Retirement"函数，
   被 `0x640804` / `0x640a2b` / `0x640af0` 三处调用。可以补丁它，
   让它从固定的存档字段读值（需要一个 spare 字段，比如 `off394`）。
   风险：改显示逻辑不等于改行为，回合结算仍用运行时值。

2. **完整 dump 运行时结构**：在游戏载入存档后，用 `gdb` 对
   `0x12d12000-0x15c50000` 全段做一次 dump，再与存档做结构化比对，
   找出转换规律。这是唯一能真正打通运行时字段的路径，但需要数小时。
